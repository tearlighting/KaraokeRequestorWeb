# Development rules

- `apps/user-web`, `apps/admin-web`, `apps/api-server` are the new TypeScript system; `legacy/php/` is compatibility code and the behavior reference. `packages/contracts/` owns shared wire contracts. See [migration/Owner matrix](docs/LEGACY_COMPATIBILITY.md) and [progress](docs/REFACTOR_PROGRESS.md).
- Inspect branch, index, untracked files and local changes first. Preserve user edits and runtime data; do not stage whole directories blindly. No automatic commit/push/force-push, `reset --hard`, volume deletion, real database recreation/schema migration or actual password changes.
- Prefer TypeScript for new features. Modify PHP for compatibility or PHP-owned modules only. Do not copy a PHP subsystem into TypeScript without behavior comparisons. Each module has one authoritative writer. A PHP Adapter call is not Node-native. Update the Owner matrix and compatibility tests whenever ownership changes.
- Keep `/api/v1` contracts compatible; validate inputs and domain outputs with Zod. Return `{ok:true,data}` or `{ok:false,error:{code,message,...}}`. Preserve actionable failures; never turn failures into empty success or retry uncertain Legacy writes.
- Authorize on the server, not in Vite. Preserve user/admin role and Origin separation, JSON/custom-header CSRF checks, HttpOnly sessions, nonempty legacy admin password and per-operation proof verification. Never trust caller role/IP headers. Bridge credentials are server-only; no credential/body logging or password persistence. Legacy Basic identity does not imply a Node session.
- Business ownership follows the current Owner matrix, not historical defaults. Phase 8 moves reservation creation/replacement to Node after equivalence tests. Its only schema addition is the separately approved, explicit `request_submission` migration; never run schema DDL during startup. PHP remains owner for search, metadata/lifecycle, settings/playback writes and unconverted legacy operations. Read-only adapters must not initialize DBs. SQLite paths are fixed/configured and WAL-aware; resolve paths explicitly, never from process CWD or browser input.
- Never expose or commit actual passwords, INI/runtime configuration, databases/journals, Bridge credentials, private keys, media, logs, node_modules/dist or test artifacts. `.gitignore` does not remove already tracked INI/PPK files; review index and diffs separately. Do not print raw configuration in diagnostics.
- Keep `origin` (tearlighting) and `upstream` (bee7813993) distinct. Analyze upstream changes before deciding whether to port to Node or retain Legacy; do not blindly overwrite Legacy or automatically merge/reset protected branches. Keep original PHP URLs available; avoid PHP → Node → PHP loops and duplicate writes.

## Commands (repository root; use npm.cmd in PowerShell)

```powershell
docker compose -f docker/compose.yaml up --build -d
docker compose -f docker/compose.yaml exec -T web php /workspace/docker/check-php.php
docker compose -f docker/compose.yaml exec -T web php /workspace/apps/api-server/tests/php/auth-check.php
docker compose -f docker/compose.yaml exec -T web php /workspace/apps/admin-web/tests/php/admin-auth-check.php
npm.cmd --prefix apps/api-server run typecheck
npm.cmd --prefix apps/api-server run build
npm.cmd --prefix apps/api-server test
npm.cmd --prefix apps/user-web run build
npm.cmd --prefix apps/user-web run test:e2e
npm.cmd --prefix apps/admin-web run build
npm.cmd --prefix apps/admin-web run test:e2e
```

All three apps have `typecheck`, `build`, `dev` scripts; install with `npm.cmd ci` in each app. Real regression tests require the synthetic isolated Compose deployment and installed Edge; test credentials must not enter traces. Never run write regression against deployed data; use the isolated test runbook below. User/admin Vite ports are 5173/5174, API 3000, Legacy 8080, bound locally. See [API runbook](apps/api-server/README.md) for environment configuration. For browser tests against an isolated API, set `API_PROXY_TARGET`, `E2E_API_BASE`, `E2E_PHP_BASE`, and `E2E_CONFIG_PATH` to that same synthetic deployment; Vite honors the process environment. Set `E2E_WEB_PORT` to a free test-only port instead of reusing an existing 5173/5174 server. Verify the proxy target before any browser test that writes.

Phase 5: Node owns GET settings projection; PHP owns PUT. Keep the single config-file mount read-only; never log/return its other fields. PHP session checks remain mandatory before/after the native read. See the compatibility document for supported INI syntax, fresh-checkout bootstrap and atomic-replacement mount limitations.

Phase 6: user/admin queue reads are Node-native; PHP remains the writer and owns initialization/WAL side-file lifecycle. Mount only `legacy/php/runtime/queue/` read-only to Node, never the whole Legacy tree. Legacy queue tickets are short-lived read-only capabilities, never Node admin sessions; preserve their signature, Origin, UA and policy-revocation checks. Runtime DB relocation requires explicit approval and stopped writers with hash verification.

Phase 7: administrator delete/up/down/warikomi are Node-owned in Compose (`YUKARI_NODE_QUEUE_MUTATIONS=1`). Mount **only the dedicated queue directory** read/write; PHP and non-root Node share group 33. PHP still owns reservation creation/automatic placement, metadata/lifecycle, settings and playback writes. Notification-only PHP reuse is not a PHP queue writer. Preserve explicit committed-but-not-notified errors; never replay a committed mutation. Migrated Legacy HTTP writes fail 410 before bootstrap; do not restore them or grant write access with read tickets. See the Phase 7 matrix for the intentionally closed bulk/restore paths.

Phase 7 write regression must use synthetic `docker/compose.isolated.yaml` and `E2E_CONFIG_PATH`, not the deployed database, even with cleanup. See [isolated test runbook](docs/LEGACY_COMPATIBILITY.md#phase-7-isolated-test-runbook). Never run host Windows and container Linux SQLite simultaneously on the same WAL fixture; cross-runtime tests run both writers in Linux containers.

Phase 8 reservation writes use Node transactions and a durable hashed submission receipt in the same queue database. The additive migration is an explicit one-time CLI step after isolated oracle tests and approval; no startup migration or automatic retry. Reuse a receipt to resolve uncertain responses; never send it in URLs/logs. Legacy `exec.php` must forward through its authenticated compatibility adapter when Node ownership is enabled; do not retain a second PHP INSERT path in the deployed mode. Core request/history/receipt writes are atomic; notification is post-commit and may return a committed-but-notified error.

Phase 9 Player Agent runs on the Windows host, never in Docker. Set `MPV_PATH` to the explicit executable; never require global `PATH`. Agent Bearer credentials are independent of user/admin sessions; only admin sessions can create/control tasks, and public playback status is sanitized. Keep task state in its separate Player Agent volume; do not add queue SQLite schema or update `nowplaying` from the test-player workflow. Agent media paths must resolve beneath its configured host media root; spawn the configured mpv executable with fixed arguments and `shell:false`. Use mpv's local JSON IPC for observed playback state/end-file events; do not infer `playing`/`completed` from process launch, duration, timers, or keyboard simulation. The Agent may connect idle without `PLAYER_TEST_VIDEO`; do not create a test task until a real media file is configured beneath `PLAYER_MEDIA_ROOT`. Host setup/validation: [Player Agent README](apps/player-agent/README.md).

Phase 10 formal autoplay is opt-in (`YUKARI_NODE_AUTOPLAY=1`) and must use the existing queue SQLite database. `playback_task` and append-only `playback_event` are the authoritative formal task/history store; the `player_agent_state` volume is limited to Phase 9 test tasks and Agent heartbeat. Their additive DDL is `apps/api-server/migrations/002-playback-task.sql`, run only with the explicit CLI after isolated tests, a consistent backup and explicit user approval; never migrate at startup or enable formal autoplay without the schema. Compose stays disabled by default. Fastify is the sole queue consumer and holds `runtime/queue/node-autoplay.owner`; guarded Legacy playback/status entrypoints fail closed while that fence exists. A separate Windows Legacy manager must be stopped unless it shares and honors the same fence. `requesttable.nowplaying` is only a compatibility projection: `再生開始待ち` on claim, `再生中` and one `playtimes` increment only after mpv confirms playback, `再生済` only after real `end-file reason=eof`, and `停止中` on confirmed stop/skip/failure. Claim, task transition, event and matching projection share a SQLite transaction. A 15-second Agent lease is renewed on poll; expired or Node-restart `claimed`/`playing` tasks become `uncertain`, keep the owner fence, and are never replayed/completed automatically. Release that fence only after an authenticated Agent confirms stop or an explicitly reviewed recovery. Admin history is read-only and must omit media paths and credentials. Preserve queue-wal-anchor. Unsupported kinds/options (including 小休止, stream/URL, loops, track/key/volume/delay) stop consumption without rewriting that row; an administrator must explicitly stop autoplay to release the owner fence. Never silently skip or hand a live queue back to Legacy.

Phase 12 adds an opt-in Fastify mode-2 manual-start strategy: the configured Legacy `playmode` is read-only, an administrator arms the Node owner fence, and explicitly starts each next request; after real EOF it waits for another click. Mode 1 remains FIFO auto-advance. Mode 3 playlist registration and modes 4/5 random selection remain unsupported and fail closed; never rewrite the saved mode to make Node eligible. Before owner handoff, reject existing Legacy active markers; `manage-mpc.php` also checks the shared owner fence at startup and during playback polling. For Docker POSIX queue paths, configure the Windows Agent's `PLAYER_PATH_MAPPINGS` JSON explicitly; each normalized POSIX source maps to an existing Windows target beneath `PLAYER_MEDIA_ROOT`. No path is inferred from a filename. Admin media checks use a short-lived Agent handoff and return only a status, never the source or Windows path. See [Player Agent path configuration](apps/player-agent/README.md) and [Phase 12 compatibility notes](docs/LEGACY_COMPATIBILITY.md#phase-12-manual-start-and-media-preflight).

Phase 13 local operation uses `scripts/windows/Start-Yukari.cmd`, `Stop-Yukari.cmd`, `Get-YukariStatus.cmd`, `Show-YukariLogs.cmd`, and `Configure-PlayerAgent.cmd`. Static production React is built into the Apache image at `/user/` and `/admin/`; `/app/` is the local portal and original PHP paths stay unchanged. Vite remains a separate dev server. The Agent's path-only config belongs under `%LOCALAPPDATA%\YukariPlayerAgent`; never store its credential there. Stop only the recorded Agent through its local pipe and Compose `web`/`api-server`; never kill all Node processes or remove volumes. Full instructions: [Windows runbook](docs/WINDOWS_LOCAL_RUNBOOK.zh-CN.md).

For browser tests, use each app's `npm.cmd ... run test:e2e`; `scripts/run-web-e2e.mjs` owns the exact Vite child so Windows teardown is deterministic. Set `E2E_WEB_PORT` to avoid developer servers, or set `E2E_BASE_URL` and `E2E_APP_PATH` to test the built Apache routes.

Phase 15 web foundations: `packages/theme/` and `packages/language/` own the user's theme/language managers and dictionaries; `packages/reactiveStore/` bridges Vue reactivity to React with `useSyncExternalStore`. Both web apps consume those shared managers through small app-local store exports; page-specific state belongs in feature/page stores where it is shared or needs coordinated updates. `packages/web-foundation/` is limited to presentation primitives and compatibility re-exports. Keep user/admin route trees independent (`/user/` and `/admin/` in production; Vite root in development), preserve protected admin session checks, and keep Apache SPA fallbacks scoped to those two prefixes so `/app/` and Legacy PHP URLs continue to resolve. Locale defaults to Japanese; translations must not alter user-entered song/singer/comment data. Theme and locale preferences are local browser preferences, not server settings. Keep framework/runtime dependencies installed per app; do not rely on a repository-root `node_modules`. Run each web app's typecheck/build/E2E scripts after changing shared foundations; Phase 15 visual/router screenshots belong in ignored `.local/phase15-shots/`.
